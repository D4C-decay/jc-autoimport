## Carrusel continuo (N+1) y paleta de marca (2026-09-28)
- **`FeaturedRail` reescrito**: la versión anterior duplicaba la lista **entera** con `translate3d(-50%)`, así que al llegar a la mitad se veían dos veces las mismas unidades seguidas. Ahora el anillo es **N+1**: N tarjetas reales + **un solo clon** del primer vehículo, y al agotar el clon se rota el anillo restando el primero y añadiendo el clon al final. Con `api.featuredVehicles(12, …)` son 12 unidades → **13 nodos, 12 slugs, nunca dos iguales visibles**.
- **El bucle lo mueve `requestAnimationFrame`**, no una animación CSS: `x` baja a `pitch / 2,1 s` por tarjeta, y al llegar a `-pitch` hace `x = 0` + rotación del anillo. Se pausa con hover/focus (`onMouseEnter/Leave`, `onFocusCapture/BlurCapture`), fuera del viewport (`IntersectionObserver`) y en móvil o `prefers-reduced-motion` (ahí es un scroller con snap, 12 tarjetas sin clon).
- **Dos trampas reales que costaron encontrar** (no volver a tropezar):
  1. **Framer Motion NO sirve para el transform del carril.** `useMotionValue` + `style={{ x }}` aplica el valor en **su propio** rAF, así que el anillo ya rotado se pintaba con el offset viejo → **salto visible de una tarjeta**. Ahora el `transform` se escribe a mano (`track.style.transform = translate3d(x,0,0)`) y la rotación del anillo va con `flushSync`, en ese orden, dentro del mismo rAF.
  2. **El pitch se mide con `offsetLeft`, nunca con `getBoundingClientRect()`.** Las tarjetas escalan (spotlight), así que la distancia visual entre rects **no** es el pitch de layout. Valores reales medidos: `offsetWidth` 384, `offsetLeft` 0/404/808, gap 20 → **pitch 404**, mientras `rect.left` daba 377-395 según la escala. Con `offsetLeft` el criterio de viraje es exacto.
- **Spotlight central** por tarjeta con la variable CSS `--k` (0 fuera, 1 en el centro): escala 0.93→1, opacidad y sombra. Los **puntos** (`rail-dot`, 12) marcan la unidad central vía `data-active`.
- **El clon es decorativo**: lleva `aria-hidden` y su enlace `tabIndex={-1}`, para no duplicar en el árbol accesible ni en el tab order.
- **SSR preservado**: `items` se inicializa con `useState(() => [...vehicles, vehicles[0]])` (antes arrancaba en `[]` y el HTML estático salía **sin ninguna tarjeta** → se había roto el SEO). Verificado en el HTML servido: 12 slugs únicos y 13 badges "Destacado".
- **Paleta de marca 60/30/10 (negro / blanco / rojo)**: se eliminó el latón. Tokens en `globals.css`: `--color-ink #08080a`, `--color-ink-2 #0e0e12`, `--color-ink-3 #16161c`, `--color-smoke #f4f4f5`, `--color-ash #96969e`, `--color-line #26262e`, `--color-signal #f02434`, `--color-signal-light #ff6b6b`, `--color-signal-dark #8f1018`. Renombrados los ~150 usos `brass` → `signal` en `apps/web/src`; el monograma SVG y el icono de Electron también son rojos (`make-icon.mjs`). **Comprobado en runtime**: badge "Destacado" `rgb(240,36,52)`, CTA en rojo, fondo `rgb(8,8,10)`, texto `rgb(244,244,245)`, **0 reglas de latón** en el CSS compilado.
- **Cómo verificar el carril en headless** (Electron no da `:hover` real, así que hay que despacharlo): `mouseover/mouseout` sobre el contenedor hace que React reciba el `onMouseEnter` sintetizado. El test definitivo no compara "la tarjeta del borde izquierdo" (da falsos positivos por la escala), sino **la posición de cada vehículo entre frames consecutivos**: un salto grande solo es bug si el vehículo sigue visible. Los saltos de `+ancho total del carril` son las tarjetas que reentran **fuera de pantalla** y son correctos.
- **Estado de la red local**: la máquina sirve en `0.0.0.0:4200` (web) y `:3000` (API), IP LAN **`192.168.11.129`**. **`ufw` está activo y NO abre 4200/3000**, así que desde el móvil u otro PC no entra: hay que ejecutar `sudo ufw allow 4200/tcp && sudo ufw allow 3000/tcp` (pendiente de que lo haga el usuario).

## Blockers
- **GitHub CLI roto**: `The token in keyring is invalid.` → hace falta `gh auth refresh -h github.com -s repo,workflow` (interactivo). **`git push` sí funciona** con las credenciales Git, así que los pushes no están bloqueados.
- `jcauto` necesita `CREATEDB` para la shadow database de Prisma (concedido con `ALTER ROLE jcauto CREATEDB`). Si migras en otra máquina, hay que repetirlo.
- Stripe/S3/email/WhatsApp usan placeholders en `.env`: las integraciones funcionan en código pero requieren claves reales para producción.
- El `.exe` de Windows va **sin firmar** (SmartScreen lo marcará). Requiere certificado de firma de código.
- En esta máquina el **proceso GPU de Electron falla** (`GPU process isn't usable`): hay que pasar `--disable-gpu` para pruebas headless. No afecta a los usuarios finales.
- `apps/web` y `apps/desktop` son paquetes independientes: un `npm install` en la raíz NO los instala.

## Decisiones clave
- **ESM**: imports relativos con sufijo `.js` (obligatorio).
- **Prisma 7**: el datasource NO lleva `url`; la URL vive en `prisma.config.ts`; cliente generado en `generated/prisma`.
- **Stripe**: `apiVersion: '2026-08-26.dahlia'` (verificada del SDK instalado).
- **Build**: `tsconfig.build.json` `rootDir: "."` → salida `dist/src/`; `start:prod: node dist/src/main.js`.
- **ioredis v6**: `import { Redis } from 'ioredis'` (named import).
- **Guards globales** en orden: `RateLimitGuard` → `JwtAuthGuard` → `RolesGuard`; `JwtModule` es `global: true` (requisito para el guard global).
- **Interceptores globales**: Logging + Transform (envuelve respuestas `{success,data,timestamp}`; DELETE/PATCH/PUT sin retorno → 404). Caché Redis por controller (no global).
- **Stripe webhook**: `rawBody: true` en `NestFactory.create` para verificar firma.
- **Flujo de reservas**: vehículo `AVAILABLE→RESERVED` al reservar; `→SOLD` en `checkout.session.completed`; `→AVAILABLE` al cancelar.
- **Auditoría**: `AuditInterceptor` global con DI de PrismaService (fire-and-forget), redacta secrets.
- **Seed argon2**: memoryCost 19456 / timeCost 2 / parallelism 1.
- **Seed config (Prisma 7)**: vive en `prisma.config.ts` → `migrations.seed` (formato string), no en `package.json`/`seed.import`.
- **Cursors de paginación**: cifrados con `JWT_ACCESS_SECRET` (cursor-encoder).
- **Full-text indexado**: columna generada `search_vector tsvector` (brand+model+description+vin) + índice `USING GIN`, creados **solo en SQL de migración** (Prisma no emite DDL para `Unsupported("tsvector")`/GIN). Posible aviso de drift en `migrate dev`; en prod usar `migrate deploy`.
- **Alias de Next (`apps/web`)**: Next infiere el *workspace root* como el repo padre y acaba usando el `tsconfig.json` del backend (sin `@/*`) → `Module not found: @/components/...`. Solución: `outputFileTracingRoot` + `turbopack.root` + alias explícito `@` en `next.config.mjs`. **No quitar esto.**
- **TypeScript pineado a `~6.0.3`** en `apps/web` y `apps/desktop`. Con `^6.0.2` npm resuelve a **7.0.2**, y Next 15 lo rechaza (`TypeScript 7.0.2 is not supported`).
- **`declare module '*.css'`** en `apps/web/globals.d.ts` (TS 6 exige declaración explícita para imports side-effect de CSS) y ese archivo debe estar en `tsconfig.json` `include`.
- **`next lint` no existe en Next 15**: el script `lint` de `apps/web` es `tsc --noEmit` (root: `npm run web:typecheck`).
- **`next start` es incompatible con `output: 'standalone'`**: `apps/web/scripts/start-standalone.mjs` copia `.next/static` y `public/` junto a `server.js` y lo arranca (`npm run web:start`).
- **BUG CRÍTICO (2026-09-28): la web servía SIN CSS y sin error visible.** Un `next build` con el server standalone corriendo **borra y recrea `.next/standalone`**, dejando al proceso vivo sirviendo HTML 200 pero con `cwd` en un directorio `(deleted)`: todos los `/_next/static/*` devolvían **HTTP 400** y la página salía sin una sola regla de estilo. Diagnóstico: comparar el hash del CSS del HTML contra `curl -o /dev/null -w '%{http_code}'` del asset; si el HTML dice 200 y el asset 400, es esto. Mitigación implementada: `start-standalone.mjs` verifica tras arrancar que el primer `/_next/static/**` responde 200 y, si no, imprime el error y sale con código 1 (`SKIP_ASSET_CHECK=1` lo desactiva). **Regla: tras cada `npm run build` en `apps/web`, reiniciar el server.** El paquete de Electron **no** sufre esto (`after-pack.mjs` copia el árbol a `resources/web`, ya verificado con el CSS dentro).
- **Levantar el server desacoplado**: `setsid nohup node scripts/start-standalone.mjs > log 2>&1 < /dev/null &` — con `nohup ... &` a secas, el tool mata el grupo de procesos al vencer el timeout y el server muere. Igual con `pkill -f 'standalone/server.js'`: el patrón coincide con la propia línea de comandos y mata el shell; usar `kill $(ss -tlnpH | grep ':4200' | grep -oE 'pid=[0-9]+' | cut -d= -f2)`.
- **Electron preload path**: `__dirname` es `dist/main`, pero el preload compilado queda en `dist/preload` → usar `path.join(__dirname, '..', 'preload', 'preload.cjs')`. El preload debe ser **CJS (`.cts`)** porque `sandbox: true` no admite preload ESM.
- **electron-builder excluye `node_modules` de `extraResources` SIEMPRE**: el server standalone se quedaba sin `require('next')`. Resuelto con el hook `afterPack: scripts/after-pack.mjs`, que copia el árbol completo (server.js + node_modules + `.next/static` + public) y valida `server.js` + `node_modules/next/package.json` antes de terminar.
- **Nombres de artefacto**: el paquete npm `@jcautoimport/desktop` no sirve como `executableName` (caracteres inválidos) → `linux.executableName: jcautoimport`; y el nombre de `.deb` por defecto (`@jcautoimport/desktop_...`) rompe la ruta → `deb.artifactName` explícito.
- **Icono sin dependencias**: `apps/desktop/scripts/make-icon.mjs` genera el PNG 512x512 codificándolo con `zlib` de Node (no hay `sharp` en `apps/*`). electron-builder deriva el `.ico` de ahí.
- **Media desnormalizada**: `primaryImageUrl`/`thumbnailUrl` en `vehicles` (path caliente sin join). `MediaService.syncPrimaryToVehicle()` mantiene ambas al subir/borrar/hacer primary. Consultas que antes resolvían subqueries por fila ahora usan columnas.
- **Compresión**: `compression` (gzip) como primer middleware de `main.ts`. `helmet` deliberadamente NO (pendiente).
- **Tests**: `npm run test` = 18 unit (vitest); `npm run test:e2e` = 4 e2e contra DB/Redis reales. La spec de health asume el `TransformInterceptor` (`data.*`).
- **Infra local**: PostgreSQL 18.6 + Valkey 9.1.2 vía systemd (no Docker). `jcauto` con `CREATEDB`.
